# @deepseek-ai/dsh-client-ui-sidebar-dag

[English](README.md) | 中文

## 概述

右侧 Sidebar 的轮次地图：把会话的每个已开始的轮次画成读者之树上的一个节点，点中一个节点就把对话移到那个轮次。树是可编辑的——节点可以重命名（用标签盖住提示词预览）、挂到另一个节点之下、提升回上一级、在同级间移动，连同子树一起折叠——而大纲始终是唯一的事实来源：节点既不会增加也不会减少，未编辑过的树读起来与朴素链完全一致。它是从引导页进入的页类型，不认领任何地址，因此不替别的查看器打开资源：`ui-sidebar-right` 里没有任何东西认识本包。它的标签、引导页入口，以及词典里为「没有轮次的会话」和「没有轮次投影的部署」准备的两行文字，都来自 `sidebarDag` 命名空间。

<a id="what-it-registers"></a>
## 注册了什么

- **类型**：`ctx.sidebarRightTabs.register(...)`，kind 为 `dag`，id 为 `@deepseek-ai/dsh-client-ui-sidebar-dag`，档位 `builtin`，没有 patterns，另有一个打开该类型的引导页入口（order 20，标题与描述取自 `sidebarDag` 命名空间，图标是共享的分支图标）。
- **正文**：以该 id 为键的 `sidebar.right.pane.tab` slot：带轮次计数的标题行、树处于编辑状态时的恢复线性控件，以及跟随暂停时它旁边就是回到当前节点的控件，其下是树。
- **树 store**：一个 Slot 标准的独占 store（`defineStore` 加 `ui-sidebar-dag.tree` 持久化键），按 tab id 分桶，保存每个 tab 的层级、标签与折叠状态。
- **标签页标题**：以该 id 为键的 `sidebar.right.pane.tab.title` slot：类型标签前的一枚 16px 共享分支图标。
- **词典**：经 `ctx.locale.register(...)` 注册 `sidebarDag` 命名空间，一次调用带上全部内置语言；缺少任何一门都会在注册时被拒绝，因此读者不会遇到半翻译的 tab。

`src/client/` 下八个源文件：`definition.tsx`（类型是什么）、`DagBody.tsx`（它画什么）、`DagTitle.tsx`（标签页标题）、`face.ts`（它如何触达对话与阅读位置）、`map.ts`（渲染列表）、`tree.ts`（可编辑树的 store）、`locales.ts`（它说什么）、`index.ts`（接线）。`src/index.ts` 是 Host 半边，不向 Host 树贡献任何东西。

<a id="the-tree"></a>
## 树

节点就是会话自己的轮次：`useProjection('turnOutline')` 按大纲顺序读成 `{ turn, prompt, response }`，本包不做事件投影，也没有第二个模型——读者之树只是大纲之上的组织层，绝不是一组新事实。提示词不带文字的轮次在树上保留原位，没有文字但有编号。大纲缺席与会话为空读起来是两行不同的文字——部署那一行与会话那一行——两者都不画树。

每一行都是真实的按钮，带节点标记、轮次号与提示词预览（或读者的标签）。当前节点——已挂载 Chat 视图报告为阅读线的那个轮次，读自可选的 `chatView` 服务按会话提供的定位——带 `aria-current` 并展开自己的回复预览，于是树保持可扫读、只有一行变高；其余行保持单行。跳转正在落位的轮次带落地态。点中一行会经 tab 的会话作用域用 `conversation.requestView({ kind: 'turn', view: 'chat', turn })` 请对话移动到该轮次，把转录带过去；当另一个视图处于活动状态时，它还会把对话切回 Chat。

读者通过 tab 的 store 编辑树：

- **重命名**：编辑控件（或 `F2`）打开行内输入框；标签盖住提示词预览，空白标签则清除回提示词。
- **挂载**：挂载控件进入挂载模式；点一个目标节点就把该节点挂到它之下、其子节点的末尾。节点不能挂到自身或其某个后代之下，且模式会一直保持，直到选中一个合法目标。
- **提升**：提升控件（或 `Shift+Tab`）把节点从父节点中提出，正好落在父节点之后，成为父节点的新兄弟。
- **移动**：上移 / 下移控件在同级间移动节点。
- **缩进**：在节点上按 `Tab` 把它挂到前一个兄弟节点之下——大纲编辑器的一贯动作。
- **折叠**：带子节点的节点有折叠控件（带 `aria-expanded`）；折叠隐藏其子树，而计数仍然说明会话有多少个轮次。
- **恢复线性**：只要存在任何层级编辑，标题行就带着恢复线性控件，把树还原为朴素大纲顺序（标签与折叠保留）。

每一次编辑都走 store 的 actions，因此编辑总是落在已放置的轮次上：树从未放置过的轮次读作未编辑的根，对它做的第一次编辑会先把当前根级顺序实体化。树按 store 的按会话持久化键保存，读者的组织在重载后仍然保留。

读者留在当前节点上时地图跟随它：每次前进都把当前行滚入视野；一旦读者把该行滚出地图自己的滚动框，树就不再在读者脚下移动，并出现回到当前节点的控件。该控件会先展开任何折叠中的祖先，再把读者带回那一行并恢复跟随；它只在当前节点滚出视野时绘制。行是键盘可达界面——一个 tab 停靠点、方向键遍历、Home/End、`Tab`/`Shift+Tab` 缩进与提升、`F2` 重命名、可见的焦点环——reduced motion 则去掉平滑滚动与落地脉冲。

读者读到的是 `sidebarDag` 词典提供的文字：类型标签与它的标签页标题、引导页入口的标题与描述、轮次计数、两行空状态、回到当前节点的控件、给没有提示词的轮次标注用的一行，以及可编辑树的每一个控件。

## 已知限制与暂缓事项

<a id="known-limitations-and-deferred-work"></a>
- **只能按 kind 打开。**类型不声明任何资源 pattern，因此没有任何地址会认领轮次地图，也无法深链到一张地图；读者只能从引导页进入它。
- **没有轮次投影的宿主与空会话读起来不一样。**词典故意把 `empty` 与 `noProjection` 分成两行：没有任何已开始轮次的会话，与不提供轮次投影的部署，两者不能读起来相同。
- **不做虚拟化。**每个节点都留在 DOM 里。树上带 `content-visibility: auto`：它包含整棵树，并在面板未显示时跳过树的内容；地图在屏幕上时树整体渲染，所以读者看着地图时的行成本并没有被削减。轮次数由会话决定，而不是由产品决定；触发虚拟列表所需的实测值——滚动或提交成本开始不可接受时的行数——没有记录。
- **失败的轮次读起来和别的轮次一样。**轮次错误、重试、压缩都不在轮次大纲里，所以失败过的轮次带着与正常答完的轮次相同的标记、编号与提示词预览，而回复预览为空。
- **读者的组织只存在于浏览器本地。**树 store 按会话持久化在客户端，读者的层级、标签与折叠在重载后仍在，但不会跟随会话到另一台设备。要把组织与 Host 同步，需要一条轮次大纲并不拥有的写入通道。
