# Agent Note: DAG-learn——右侧边栏的轮次地图

Status: implemented

[English](2026-09-11-dag-learn-turn-map-sidebar.md) | 中文

## 问题

长会话是一条读者看不见的链。产品只有一个轮次导航器，而且它长在 Chat 转录内部：`TurnNavigator` 在消息旁边画一条细刻度条，它的刻度能把转录滚到某个轮次，目标未加载时则分页历史。这条刻度条只有几像素宽、不带文字，且只能从它自己滚动的那块界面进入。读者在任何其他界面工作——右侧边栏的文件树或文档预览、Trajectory 账本、宽屏的多窗格排布——都没有会话的地图，也没有办法移动转录。

两个事实让一张侧边栏地图做得便宜，且两者都是本设计的承重结构：

- 宿主已经对整份日志投影出 `turnOutline`：每个已开始的轮次，按升序，带一个有界的提示词预览、一个有界的落定回复预览，以及该轮次的 `turn/start` seq。任何会话作用域的 slot 占用者都能通过 `useProjection` 读到它，无需自己投影事件。
- Chat 视图已经实现了轮次导航：已加载目标滚动落地，未加载目标按大纲 seq 分页历史后落地。

缺的不是轮次模型，也不是落地例程，而是一条受支持的通道：让对话外壳之外的插件能请对话移动，也让 Chat 视图之外的插件能知道转录当前在哪。这两件事此前都私有于拥有它们的包：请求状态存在一个 Slot store 里，渲染器按注册项与作用域解析它，没有公开访问器；Chat 的当前轮次值是组件状态。

## 决策

DAG-learn 是一张只读的轮次地图，是客户端包 `@deepseek-ai/dsh-client-ui-sidebar-dag` 里的一个右侧边栏 tab 类型。每个已开始的轮次都是竖向节点链上的一个节点，来源是宿主自己的轮次大纲；选中节点即把对话移动到该轮次。该类型在文件树旁边注册一个引导项，因此没有记忆页面的窗格会打开引导页——曾经默认是文件树的地方，现在是一个二选一的入口，而默认页的这一翻转正是本决策的后果之一。地图不持久化任何东西、不编辑任何东西、不拥有任何轮次数据：它是一个投影消费方，外加两条薄薄的跨包接缝。

三条接缝撑起它，各自归已经拥有对应状态的包所有。

1. **导航——`ui-conversation`。** `IConversation` 是其他插件可以触及的、按作用域寻址的对外面，它带上了 `requestView(request)`，接收那个由被寻址视图消费并确认的一次性 `ConversationViewRequest`。在对话外壳内部，这正是 store 的那个一次性请求动作所做的事：激活所寻址视图的目标源、记录视图偏好、发布请求。请求是带判别标签的联合体——视图自有寻址用的不透明 `focus` 身份，或面向轮次型视图的 `turn` 数字。Trajectory 保持自身行为，改为读 `focus` 那一支。
2. **轮次寻址——类型化，而非编码。** 轮次按数字寻址。客户端 bundle 不允许从另一个插件导入值——bundle 纯净门禁会拒绝跨插件值导入，并把协作导向 cordis 服务——因此即便 `ui-chat` 导出格式化函数也到不了地图手里。与其在两个包里各拼一遍同一种格式，不如让请求把轮次作为类型化字段携带，于是根本不存在会漂移的格式。
3. **当前位置——`ui-chat`。** `ui-chat` 提供客户端服务 `ctx.chatView`，其 `location(sessionId)` 以按会话的 source 报告 Chat 视图自己的 `{ activeTurn, busyTurn }`。客户端 bundle 不允许从另一个插件导入值，因此 cordis 服务是跨插件值唯一能走的通道；地图用 `ctx.get` 可选地读取它，与今天读取 `chatFileMentions` 的方式相同。Chat 视图未挂载时该 source 报告空位置；服务缺席则地图不画当前位置标记。

### 外部生产者

视图请求的机关在对话外壳内部是完整的，在外壳之外则够不着。请求存在持有 `view` 与 `viewRequest` 的按会话 Slot store 里；渲染器按注册项与作用域解析那个 store，没有任何服务方法或公开访问器能到达它。

因此外壳是**施加方**，而不是第二个所有者。已挂载的对话外壳把自身注册为所属会话在 conversation 服务上的请求施加方；`requestView` 把请求交给该施加方，由它完全按外壳内调用方的做法经 store 动作写入。store 仍是请求唯一的在生所有者，服务自身不持有任何请求状态。没有已挂载外壳的会话也就没有施加方，此时调用**响亮失败**而不是把请求丢掉：不变式是右侧边栏 tab 与其所属会话的已挂载对话区共存，所以施加方缺席是值得一条消息的异常，而不是沉默。

生产者经会话作用域触达该动词，与 `ui-conversation` 自己的按作用域寻址调用方所走的路线一致：`sessions.scope(sessionId)`，再从其中解析出 `conversation` 服务。

### 节点来源

`useProjection('turnOutline')` 产出 `TurnOutlineEntry[]`——`{ turn, seq, prompt, response }`——按 `turn` 严格递增。预览排除注入的上下文与工具结果；回复预览在该轮次落定后才出现。

由此得出的后果塑造了这张地图：

- 仍在生成的轮次已经是一个节点，有提示词预览与空的回复预览；回复预览在轮次落定时补上，节点不会出现、消失或重排。
- 不需要第二个来源。地图不读 Chat 目标快照，因此它独立于 Chat 视图，在未挂载 Chat 的部署与视图配置下照样渲染。
- 投影的预览在线上边界处已经有界，所以地图不再重新定界；溢出是视觉裁切，不是新的上限。

投影值跨线，而投影类型表已经把它带过了这道线：`turnOutline` 声明在 `SessionProjectionMap` 里，因此 `useProjection('turnOutline')` 交给地图的就是类型化条目，地图自身不做任何收窄。

### 选中一个节点

tab 的会话作用域提供会话，节点提供自己的 `turn`：

1. 地图调用 `conversation.requestView({ kind: 'turn', view: 'chat', turn })`；
2. 外壳施加请求，Chat 视图消费它：已加载的轮次走导航栏已加载刻度所用的同一条路径；已加载窗口之外的轮次则用大纲里的 `seq` 装填既有的待落地状态，先经 `loadThrough` 分页历史，再落地；
3. 请求被确认。

无法解析的轮次——节点对应的轮次因历史在地图脚下移动而已不存在——会被确认且无可见变更。这个手势是用户对过期数据的动作，不是配置错误，而且它不会让一次性请求卡死。

### 地图自身的行为

读者在尾部时地图跟随尾部；读者一旦把当前节点滚出地图自己的滚动框就暂停跟随——与 Chat 转录和 Trajectory 账本一致。「返回当前」控件在跟随暂停期间把读者带回当前节点并恢复跟随；该控件只在当前节点滚出视野时出现。

行是等密度、紧凑的：节点标记、轮次号、提示词预览。只有当前节点展开回复预览，于是链保持可扫读，视线一次落在一行上。跳转在飞行中的节点带落地态；当前节点带 `aria-current`。

地图是键盘可达界面：一个 `nav` 地标内是真实按钮组成的列表，roving tabindex 与方向键遍历、Home/End，焦点环保持可见，reduced-motion 关闭平滑滚动与落地脉冲。链不设内容宽度上限——标记列与脊柱保持各自的固定留白，除当前节点外的每一行都保持单行省略——因此窗格变宽时变宽的是预览行，而不是行本身。

空会话显示一行；缺少投影的部署显示**另一行**，因此缺投影永远不会被当成空会话呈现。

## 本版不做的事

- 无分支：fork、子代理子会话、重试都不是节点。线性链是有向无环图的退化情形，而这就是这一版画的全部图。
- 无节点编辑、命名、标注、持久化、搜索、过滤、迷你地图、缩放。
- 无左侧边栏面板，也不在非浏览器 UI 面上提供入口。
- 不做虚拟列表。链把每个节点都留在 DOM 里，并带 `content-visibility: auto`：它包含整条链，并在面板未显示时跳过链的内容；而触发虚拟化所需的实测值目前未知——本包 README 把这一缺口与其他已知限制一并记录。
- 不改变 Trajectory 聚焦路径、转录导航栏，或任何既有的轮次导航行为。

## 曾考虑的替代方案

**为什么不让 `ui-chat` 自建定位服务（`chatLocation.reveal` / `activeTurn`）供地图依赖？** 这样改动集中在一个包里，但 Chat 视图并非总是挂载——读者可能正在看 Trajectory 账本——于是 `reveal` 无处落地；而把对话切回 Chat 又需要活在对话外壳里的视图选择。这个设计最终还是要伸进 `ui-conversation`，还额外多了一条「侧边栏插件依赖 Chat 插件」的边。

**为什么不由 `ui-chat` 导出焦点编码供生产者调用？** 客户端 bundle 不允许从另一个插件导入值：bundle 纯净门禁拒绝跨插件值导入，并把协作导向 cordis 服务。因此导出的格式化函数到不了地图手里，只剩两个选择——在两个包里各拼一遍同一种格式，或把轮次做成请求上的类型化字段。类型化字段删掉了这个格式，而不是复制它。

**为什么不把地图的 tab 直接注册进 `ui-chat` 包内，直接共享那个跳转闭包？** 那是改动最小的方案：完全不需要新接缝。它同时把一块侧边栏界面塞进了 Chat 目标包，违背「一个包一个角色」的布局，而且让这个实验的下线或改动变成对一个核心包的改动。

**为什么不直接往对话 store 里写请求？** store 实例由 Slot 渲染器为特定的注册项与作用域解析，按设计没有公开访问器；开放一个就等于把外壳状态的可变句柄交给每个插件。施加方把写集留在了它该在的地方。

**为什么不从侧边栏直接用浏览器自己的 scroll into view？** 转录会虚拟化并分页；DOM 级滚动到不了一个未加载的轮次，而且页面位移时会静默显示错误的位置。Chat 视图的落地例程之所以存在，正是因为这不是一个滚动位置问题。

**为什么节点列表不来自 Chat 快照而来自投影？** 快照只持有已加载窗口，所以长会话早期的轮次在分页进来之前会从地图上缺失——与「地图」正相反。投影的存在就是为了描述客户端尚未加载的轮次。

## 后果

- 一个右侧边栏 tab 类型把会话的每个已开始轮次按升序画成链上节点，来源是 `turnOutline` 投影，且地图包内没有任何事件投影。
- 选中节点把对话移动到该轮次，被寻址视图是 Chat：已加载轮次走既有的已加载刻度路径落地，未加载轮次按大纲 seq 分页历史后落地。当另一个对话视图处于活动状态时选中节点，会把对话切回 Chat 并落在该轮次，因为请求本身就带着视图选择。
- 一次性请求是带判别标签的联合体，在被寻址视图 id 旁携带一个类型化的分支。store 此前发布的字符串焦点编码没有了，包之间也不共享任何轮次格式化函数：客户端 bundle 禁止跨插件值导入，因此轮次是作为字段传来，而不是作为两个包都得跟着保持一致的格式。
- `requestView` 在两处响亮失败：被寻址视图未注册时给出 `ui-conversation: no Conversation View "<view>" is registered`，被寻址会话没有已挂载外壳时给出 `conversation.requestView: session "<id>" has no mounted conversation shell`。两条路都不会静默丢掉请求。
- 没有记忆页面的窗格的默认页现在是引导页而不是文件树：`files`（order 10）与 `dag`（order 20）是仅有的两个引导项，而入口数不为一时该界面会打开引导页。文件树仍可用 `openTab('files')` 直达。
- 会话的阅读位置作为客户端状态跨包传递，`ui-chat` 是它唯一的写入方：Chat 视图未挂载的会话报告 `{ activeTurn: null, busyTurn: null }`，因此没有内容在展示位置时地图也不标记任何位置；未挂载 Chat 插件的装配则完全不画当前位置标记。
- 投影是可选的。不提供轮次大纲的部署会画出它自己那一行，与空会话那一行不同，而链照常渲染。
- 链把每个节点都留在 DOM 里，并带 `content-visibility: auto`：面板未显示时它会跳过链的内容；行数由会话的轮次数决定，而在产品之下没有任何东西给轮次数设上限。

本决策让出的代价：

- **施加方不变式是约定，不是结构性保证。** 请求经外壳注册的施加方到达该会话的外壳，而没有任何东西阻止某会话的右侧边栏 tab 与另一个会话的外壳在浮动面板里共存——那时跳转就会在读者期待它工作的地方响亮失败。组合测试把已交付的这套安排钉住。
- **改动落在两个核心包的热路径上。** 该动词写入对话 store 的视图选择，而 Chat 视图消费请求所依赖的状态，正是它滚动时驱动的同一份状态。两个包的测试套各自覆盖自己的路径。
- **请求契约是带判别标签的联合体。** Trajectory 读 `focus` 那一支，store 动作按到达的分支发布，因此仍假设单一字符串焦点的消费方不再能编译。
- **在实测之前不做虚拟化。** 行数由会话轮次数决定，而轮次数不被产品设上限。地图可见时链就在屏幕上、整体渲染，`content-visibility: auto` 在那里不削减任何成本；触发虚拟化所需的实测值没有记录，也不靠猜。
- **引导项移动了右侧边栏的默认页。** 两个引导项意味着新窗格打开的是引导页而不是文件树。这是接受而不是规避的：当某一个类型不再是唯一时，引导页正是设计中的选择入口；而另一条路——不注册引导项——会让地图在界面上无从发现。
- **地图展示结构，不展示健康状态。** 轮次错误、重试、压缩都不在投影里，所以一个失败的轮次读起来和别的轮次一样。要呈现失败态需要另一个来源，本版有意不做。

## 暂缓事项

- 链不设内容宽度上限，两种面板宽度下都保持同一套行节奏；全宽面板是否需要内容宽度上限或两行预览，尚未决定。
- 链没有在 tab 的菜单座位（`sidebar.right.tab.menu.item`）暴露「跳到该轮次」动作；行是它唯一的入口。
- 转录导航栏保留自己的脚本内锚点路径，没有迁到外部生产者接缝上，因此两块界面仍走不同的路线驱动轮次导航。
